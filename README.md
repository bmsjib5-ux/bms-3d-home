# แผนที่ 3 มิติ เส้นทางผู้ป่วยนอก (Patient Journey 3D)

จอแสดงภาพรวมผู้ป่วยนอกแบบ 3 มิติ อ่านข้อมูลสดจาก HOSxP ผ่าน BMS Session
เห็นได้ทันทีว่าตอนนี้คนไข้อยู่จุดไหน จุดไหนคนแน่น และรอนานเท่าไร
เหมาะกับจอติดผนังในห้องประชุม/ศูนย์ควบคุม

ทำงานด้วย HTML ไฟล์เดียวต่อหน้า + three.js ไม่ต้อง build ไม่ต้องติดตั้งอะไรนอกจากเปิดเซิร์ฟเวอร์เล็ก ๆ ในเครื่อง

| ไฟล์ | คืออะไร |
|---|---|
| `index.html` | ตัวอย่างแอนิเมชันขั้นตอนการรับบริการ (ไม่ต้องต่อฐานข้อมูล) |
| `live.html` | **ตัวจริง** — คนไข้ในฉากคือคนไข้จริงของวันนี้ |

## วิธีเปิดใช้

1. ดับเบิลคลิก `start.bat` — ใช้ Python 3.7+ ถ้ามี ไม่มีก็ใช้ Windows PowerShell ที่ติดมากับเครื่อง
2. เบราว์เซอร์จะเปิด <http://localhost:8803/live.html>
3. วาง **Session ID** ที่ขอจาก HOSxP (เมนู BMS Session) ในหน้าต่างที่ขึ้นมา

> **ห้ามเปิดไฟล์ด้วยการดับเบิลคลิก** (`file://`) — tunnel ของ HOSxP ปฏิเสธคำขอที่ไม่มี origin
> ต้องเปิดผ่าน `start.bat` เท่านั้น (`serve.py` / `serve.ps1` ทำหน้าที่เสิร์ฟไฟล์ + ส่งต่อคำขอไป `*.hosxp.net` พร้อมใส่ CORS/User-Agent ให้)

ให้เครื่องอื่นในวงเปิดจอนี้ได้: รัน `Enable-LAN.bat` หนึ่งครั้งที่เครื่องที่เปิด `start.bat`
(เปิดไฟร์วอลล์พอร์ต 8803 + จอง URL ให้ PowerShell ฟังได้โดยไม่ต้องเป็นแอดมิน) แล้วเครื่องอื่นเปิด `http://<ไอพีเครื่องนั้น>:8803/live.html`

เปลี่ยนพอร์ตได้ที่บรรทัด `set PORT=` ใน `start.bat`

## ตัวเลือกใน URL

| ตัวเลือก | ผล |
|---|---|
| `?demo=1` | โหมดจำลอง ไม่ต้องมี session (ใช้ดูหน้าตาหรือสาธิต) |
| `?bms-session-id=xxxx` | ใส่ session มาใน URL เลย (ใช้กับจอที่เปิดเองตอนเครื่องบูต) |
| `?tour=1` · `?tour=12` | เริ่ม "ทัวร์จุดบริการ" เอง — กล้องซูมเข้าทีละจุดแล้ววนรอบ (ค้างจุดละ 12 วินาที) |
| `?tourEvery=5` | ถ้าไม่มีใครแตะจอครบ 5 นาที ให้ทัวร์เองรอบหนึ่งแล้วกลับภาพรวม |
| `?beds=300` | ขยายผังอาคารตามขนาดโรงพยาบาล (60 / 120 / 200 / 300 / 800 เตียง) |
| `?perf=1` | เปิดตัววัดประสิทธิภาพ (`window.__pj3d`) |

ทุกอย่างตั้งได้ในหน้าตั้งค่าในตัวเช่นกัน และจำค่าไว้ใน localStorage ของเครื่องนั้น

## ข้อมูลจริงมาจากไหน

| ในฉาก | ในฐาน HOSxP |
|---|---|
| คนไข้อยู่จุดไหน | `ovst.cur_dep` ของ visit วันนี้ → จับคู่ชื่อแผนก (`kskdepartment`) เข้ากับจุดบนผัง แก้รายแผนกได้ในตั้งค่า |
| เวลารอ | `ovst.cur_dep_time` ถ้ามี ไม่งั้นนับจากที่หน้าจอเห็นคนไข้ย้ายจุด |
| หน้าตาตัวละคร | `patient.pname` / `sex` / `birthday` (ใช้แค่เลือกรูปร่าง ไม่แสดงชื่อ) |
| คิวที่ห้องแล็บ / X-ray | เฉพาะใบที่ห้องยังไม่รับ — `lab_head.lab_receive <> 'Y'`, `xray_report.accept_date IS NULL` |
| Admit เข้าหอ | `ovst.an` → `ipt` (เวลาเข้าหอ, หอผู้ป่วย) |
| จำนวนเจ้าหน้าที่ที่ login อยู่แต่ละจุด | `doctor_online` ที่ใช้งานใน 15 นาที แยกบทบาทจาก `doctor_position` |
| ดูย้อนหลัง (replay) | `opd_dep_queue` — เล่นย้อนทีละชั่วโมงหรือทั้งวัน |

ดึงข้อมูลใหม่ทุก 20 วินาที และส่งเฉพาะคำสั่ง **SELECT** ผ่าน `/api/sql` ของ BMS Session ไม่มีการเขียนกลับ

เมื่อหลายเครื่องเปิดจอพร้อมกัน เซิร์ฟเวอร์จะ **แคชคำตอบ `/api/sql` ร่วมกัน 15 วินาที** ฐานข้อมูลจึงเห็นภาระประมาณจอเดียว
(ปิดด้วย `BMS_PJ3D_CACHE_SEC=0` · ดูสถิติที่ `/cache-stats`)

## สิ่งที่ควรรู้

- คนไข้ที่ `an` ไม่ว่าง (admit แล้ว) ไม่แสดงตัวในฉาก แต่ยังนับในการ์ด "Admit เข้าหอ"
- **มาวันนี้** = รวม admit · **อยู่ใน รพ.** = มา − กลับบ้าน − admit
- ตำแหน่งจุดบริการบนผังเป็นค่าเริ่มต้นของโรงพยาบาลหนึ่งแห่ง ย้าย/เพิ่ม/ซ่อน/เปลี่ยนชื่อจุดเองได้ในหน้าตั้งค่า
- เกณฑ์สีเวลารอ (เหลือง/แดง) ตั้งแยกได้ทุกจุด
- ภาพเคลื่อนไหวจะเดินเฉพาะตอนหน้าเว็บมองเห็นอยู่ (เบราว์เซอร์หยุด `requestAnimationFrame` เมื่อแท็บถูกซ่อน) — ข้อมูลยังรีเฟรชตามปกติ
- ต้องมีสิทธิ์ BMS Session ของโรงพยาบาลตัวเอง เครื่องมือนี้ไม่มีข้อมูลคนไข้ติดมาด้วย
